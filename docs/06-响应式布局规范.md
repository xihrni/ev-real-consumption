# 06 · 响应式与布局规范

> 实现：[src/style.css](../src/style.css) 末尾的 `@media` 块（`style.css:472-668`）
> 实测数据：2026-10-05 用 Playwright 在 6 个视口量取

---

## 1. 断点体系

| 断点 | 视口范围 | 布局形态 | 导航 |
|---|---|---|---|
| **移动** | < 700px | 单列堆叠 | 底部 Tab 通栏 |
| **窄平板** | 700 ~ 899px | 单列加宽 | 底部 Tab 通栏 |
| **桌面** | 900 ~ 1439px | Grid + 双列并排 | **左侧竖排** |
| **超宽** | ≥ 1440px | Grid + 更宽双列 | 左侧竖排（更宽） |
| 弹窗居中 | ≥ 560px | 居中卡片 | — |

### 1.1 为什么是这三个数

| 断点 | 依据 |
|---|---|
| **700px** | 平板最小可用宽度。768px 的 iPad 竖屏落在此区间，单列仍舒适 |
| **900px** | **关键决策点**。900px 减去 248px 侧栏 = 652px，够放「340px 表单 + 300px 列表」双列 |
| **1440px** | 常见 2K 显示器逻辑宽度（2560 物理 ÷ 1.25 缩放）。此宽度下若不加档，1600~1900px 屏幕会看到大片空白 |
| **560px** | 弹窗从底部抽屉切换为居中卡片的时机。低于此宽度抽屉形态更自然 |

**900px 的双重性**：它同时是「桌面形态生效」和「侧栏出现」的点。**两个含义必须同一个断点**——否则会出现「桌面布局但底部 Tab 悬空」的中间态。

## 2. 各档布局详解

### 2.1 移动端（< 700px）

```
┌─────────────────────┐
│  Header (sticky 56px)│
├─────────────────────┤
│  Hero 车辆卡         │
├─────────────────────┤
│  指标卡 2×2          │
│  ┌────┐ ┌────┐      │
│  │电耗 │ │均价 │      │
│  └────┘ └────┘      │
│  ┌────┐ ┌────┐      │
│  │里程 │ │花费 │      │
│  └────┘ └────┘      │
├─────────────────────┤
│  图表 220px × 4      │
│  （单列堆叠）         │
├─────────────────────┤
│  记录表单            │
│  记录列表            │
├─────────────────────┤
│ Tab栏 (fixed 64px)   │
└─────────────────────┘
```

**关键约束**：
- `.content` 底部留 `calc(var(--tab-h) + var(--safe-bottom) + 20px)`，避免最后一项被 Tab 栏遮住
- 图表高度 `var(--chart-h, 220px)`

### 2.2 窄平板（700 ~ 899px）

只做**温和加宽**，仍是单列：

| 项 | 移动 | 窄平板 |
|---|---|---|
| `.content` max-width | 760px | 900px |
| 指标卡列数 | 2 | **4** |
| Hero 宽度变量 | `--hero-max: 760px` | `--hero-max: 860px` |

### 2.3 桌面（900 ~ 1439px）

```
┌──────────┬──────────────────────────────────┐
│          │  Header (sticky 60px, 跨两列)     │
│  侧栏    ├──────────────────────────────────┤
│  248px   │  Hero 车辆卡 (--hero-max 1216px)  │
│          │  ┌────────────┐ ┌──────────────┐ │
│  概览 ●  │  │ 指标卡×4   │ │              │ │
│  记录    │  └────────────┘ └──────────────┘ │
│  分析    │  ┌────────────┐ ┌──────────────┐ │
│  数据    │  │ 图表 340px │ │ 图表 340px   │ │
│  帮助    │  └────────────┘ └──────────────┘ │
│          │  ┌────────────┐ ┌──────────────┐ │
│          │  │ 图表       │ │ 图表         │ │
│          │  └────────────┘ └──────────────┘ │
│  ↑sticky │                                  │
│  固定    │  (滚动时侧栏不动)                  │
└──────────┴──────────────────────────────────┘
```

**关键结构**：`.app-shell` 从 `flex column` 改为 `grid`：

```css
.app-shell {
  display: grid;
  grid-template-columns: 248px minmax(0, 1fr);
  grid-template-rows: auto minmax(0, 1fr);   /* header 占第一行 */
  min-height: 100vh;
}
.app-header { grid-column: 1 / -1; grid-row: 1; }   /* 跨两列 */
.app-body   { grid-column: 2;      grid-row: 2; }
.tab-bar    { grid-column: 1;      grid-row: 2; }
```

> **用显式 grid 定位而非 DOM 顺序**：`.tab-bar` 在 DOM 中位于 `.app-body` 之后，但通过 `grid-row/column` 定位到左侧。这样移动端的 DOM 顺序（内容在前、导航在后）保持不变，桌面端靠 grid 重排。

**记录页双列**（`.rec-page`）：

```css
grid-template-columns: minmax(340px, 460px) minmax(0, 1fr);
gap: 20px;
align-items: start;
```

`align-items: start` 很重要——**防止左侧较矮的表单被拉伸到与右侧长列表等高**。

**概览图表双列**（`.chart-card`）：

```css
grid-template-columns: 1fr 1fr;
gap: 10px 32px;
```

`.card-head` 用 `grid-column: 1 / -1` 跨两列，4 个 `.chart-block` 排成 2×2。

### 2.4 超宽（≥ 1440px）

**目的：消除 1600~1900px 屏幕的大片空白。**

| 项 | 桌面 | 超宽 | 变化 |
|---|---|---|:---:|
| 侧栏 | 248px | **268px** | +20 |
| `.content` max-width | 1280px | **1616px** | +336 |
| 图表高 | 340px | **400px** | +60 |
| 卡片内边距 | 20px | **24px** | +4 |
| 指标数字 | 27px | **30px** | +3 |
| 卡片标题 | 17.5px | **19px** | +1.5 |
| 记录表单列 | 340~460px | **440~520px** | +100 |
| 图表列间距 | 32px | **40px** | +8 |
| 导航项字号 | 15px | **15.5px** | +0.5 |
| `--hero-max` | 1216px | **1536px** | +320 |
| `--hero-inset` | 32px | **40px** | +8 |

**实测内容宽度**（Playwright 2026-10-05 量取 `.content` 的实际渲染宽度）：

| 视口 | 侧栏 | `.content` 实际宽 | 说明 |
|---|:---:|:---:|---|
| 1024 | 248 | 776 | 未触到 max-width |
| 1280 | 248 | 1032 | 未触到 max-width |
| 1600 | 248 | 1332 | 未触到 max-width |
| 1920 | 268 | 1616 | 触到超宽档 max-width 上限 |

> 1600 视口下若继续走桌面档（max-width 1280），两侧会各留 160px 空白——这就是为什么要在 1440px 加一档。1920 下内容占 1616px，其余留白由 268px 侧栏和容器余量承担。

## 3. 桌面化改造清单

移动 → 桌面需要改这些：

| # | 改动 | 方式 |
|---|---|---|
| 1 | 整体 flex → grid | `.app-shell` |
| 2 | 底部 Tab → 左侧栏 | `.tab-bar` `position: fixed` → `sticky` + `flex-direction: column` |
| 3 | 清 fixed 残留偏移 | 显式 `left/right/bottom: auto` |
| 4 | 侧栏背景铺满 | `.app-shell::before` 占 `grid-row: 2` |
| 5 | 记录页单列 → 双列 | `.rec-page` |
| 6 | 图表单列 → 双列 | `.chart-card` |
| 7 | 指标卡 2 列 → 4 列 | `.stats-grid` |
| 8 | 内容区加宽 | `.content` max-width |
| 9 | 字号分级放大 | 见 §5 |
| 10 | 弹窗抽屉 → 居中卡片 | `@media (min-width: 560px)` |
| 11 | 底部留白移除 | `.content` 覆盖 `padding-bottom` |
| 12 | Toast 上移 | `.toast-host` 从底部 Tab 高度 → `32px` |

### 3.1 侧栏 sticky 的实现要点

```css
.tab-bar {
  position: sticky;        /* 从 fixed 改来 */
  top: var(--header-h);    /* 60px，紧贴 header 下方 */
  left: auto;              /* ⚠️ 必须显式清掉 fixed 的 left:0 */
  right: auto;             /* ⚠️ 必须清掉 fixed 的 right:0 */
  bottom: auto;            /* ⚠️ 必须清掉 fixed 的 bottom:0 */
  align-self: start;       /* ⚠️ 关键：不被 grid 行拉伸 */
  height: calc(100vh - var(--header-h));
}
```

**三个容易踩的坑**：

| 坑 | 后果 | 解决 |
|---|---|---|
| 不清 `left/right/bottom` | sticky 元素被残留偏移约束，行为异常 | 显式设 `auto` |
| 不写 `align-self: start` | 侧栏被拉伸到内容行等高，`top: 60px` 失效 | 加 `align-self: start` |
| 只写 `top` 不写 `height` | 侧栏只有导航项高度，背景不完整 | 显式设 `height: calc(100vh - header)` |

### 3.2 侧栏背景铺满

sticky 侧栏只有一屏高，页面滚动后下方会露出 `--bg` 底色。解决：

```css
.app-shell::before {
  content: '';
  grid-column: 1;
  grid-row: 2;             /* 与 .tab-bar 同行 → 自动拉伸到整行高度 */
  background: var(--surface);
  border-right: 1px solid var(--border);
}
```

`::before` 作为 grid item 默认 `stretch`，会自动填满整行，滚动时下方也是白色。`.tab-bar` 的 `z-index: 40` 高于它（`::before` 无 z-index），所以导航浮在背景层之上。

## 4. Hero 车辆卡的对齐机制

Hero 卡在 `.app-body` 内、`<main class="content">` **之外**，所以它的宽度不会自动跟内容区一致。用三个变量同步：

```css
:root {
  --hero-max: 760px;    /* 移动端：与 .content max-width 一致 */
  --hero-inset: 14px;   /* 移动端：与 .content 左右 padding 一致 */
  --hero-mt: 10px;
}
.hero-card {
  margin: var(--hero-mt) auto 0;
  max-width: var(--hero-max);
  width: calc(100% - var(--hero-inset) * 2);
}
```

**各断点同步值**：

| 断点 | `.content` max-width / padding | `--hero-max` | `--hero-inset` | `--hero-mt` |
|---|---|:---:|:---:|:---:|
| 移动 | 760px / 14px | 760px | 14px | 10px |
| 700+ | 900px / 20px | 860px | 20px | 18px |
| 900+ | 1280px / 32px | 1216px | 32px | 24px |
| 1440+ | 1616px / 40px | 1536px | 40px | — |

**规律**：`--hero-max = .content 的 max-width - 左右 padding 之和`

验证：桌面 `1280 − 32×2 = 1216` ✅　超宽 `1616 − 40×2 = 1536` ✅

> **为什么用变量而不是 `max-width: 100%`**：Hero 卡必须在 `.content` 外面（视觉上作为跨栏标题），但要和内容区边缘对齐。用变量是唯一干净的做法。**改 `.content` 的 max-width 或 padding 时，必须同步改这两个变量。**

## 5. 字号放大策略

**不是整体 `scale()`，而是按信息层级分级放大**：

| 层级 | 移动 → 桌面 → 超宽 | 增幅 |
|---|---|:---:|
| 统计大数 | 23 → 27 → 30px | **+30%** |
| 卡片标题 | 16 → 17.5 → 19px | +19% |
| 导航项 | 11 → 15 → 15.5px | +41% |
| 正文 | 15 → 15 → 15px | **0%** |
| 辅助说明 | 12 → 13px | +8% |
| 徽章 | 11 → 11px | 0% |

**设计意图**：
- 数字和标题是「扫视焦点」，放大后桌面端一眼可读
- 正文保持 15px（本来就可读），放大反而显得臃肿
- 辅助与徽章小幅放大，避免抢焦点

> ⚠️ **移动端完全不受影响**：所有放大规则都写在 `@media (min-width: 900px)` 内。

## 6. 图表高度机制

```css
:root { --chart-h: 220px; }                     /* 移动端兜底 */
@media (min-width: 900px)  { :root { --chart-h: 340px; } }
@media (min-width: 1440px) { :root { --chart-h: 400px; } }
```

`BaseChart.vue` 读取：

```vue
<div :style="{ width: '100%', height: height || 'var(--chart-h, 220px)' }"></div>
```

**优点**：
- 改高度只需改一个变量，不用逐个组件调整
- 移动端不设变量也不会失效（有 `220px` 兜底）
- `height` prop 仍可覆盖（当前无使用场景，保留给未来的小图场景）

## 7. 断点维护规范

所有 `@media` **集中在 `style.css` 末尾**，按断点从小到大排列。

| 规则 | 说明 |
|---|---|
| 🚫 组件内不写 `@media` | 单个组件内出现媒体查询，说明布局耦合了 |
| ✅ 必须用 `min-width` | 移动优先，避免 `max-width` 的降级陷阱 |
| ✅ 变量在 `:root` 内覆写 | 集中管理，不散落在各组件 |
| ✅ 改断点值前先算 Hero 变量 | 见 §4 |
| ✅ 改 `.content` 宽度同步 Hero | 见 §4 |

**CSS 顺序陷阱**：`@media (min-width: 560px)` 写在文件**最后**，但 560 < 900，逻辑上"后写的应该赢"。因为它只改 `.mask` 和 `.sheet`（与 900px 断点里的规则不冲突），所以无影响。**新增断点时务必确认选择器不重叠。**

## 8. 验证清单

改动布局后，**必须**在以下视口实测（2026-10-05 已建立此流程）：

| 视口 | 验证点 |
|---|---|
| 390 × 844 | 移动端无回归：底部 Tab、指标 2 列、图表 220px |
| 768 × 800 | 窄平板边界：指标是否 4 列 |
| 1024 × 800 | 桌面下界：侧栏 248px、双列是否拥挤 |
| 1280 × 900 | 常见笔记本：内容 1032px |
| 1600 × 950 | 桌面舒适区 |
| 1920 × 1000 | 超宽是否留白过多 |

**Playwright 量取脚本要点**：

```js
const m = await page.evaluate(() => {
  const g = (sel, prop) => { const e = document.querySelector(sel); return e ? getComputedStyle(e)[prop] : null }
  const r = (sel) => { const e = document.querySelector(sel); return e ? Math.round(e.getBoundingClientRect().width) : null }
  return { contentW: r('.content'), tabFont: g('.tab-bar .tab','fontSize'), statV: g('.stat .v','fontSize') }
})
```

> ⚠️ **mock 生产数据时**：`sessions` 的 `vehicle_id` 要映射为 `vehicleId`，否则记录数为 0，会误判成"布局坏了"。详见 [10-数据模型 §7](10-数据模型.md)。
