# 07 · 交互状态设计

> 加载、空、错误、确认四类状态的统一规范
> 目的：避免"同一个错误在不同页面表现不一致"

---

## 1. 状态分类与呈现方式

| 状态 | 呈现方式 | 用在哪 | 实现 |
|---|---|---|---|
| **加载** | 品牌渐变启动页 | 应用启动 | `.boot` |
| **加载** | 按钮内联 loading | 提交表单 | `loading` 态 |
| **空** | 图标 + 说明 + 引导 | 无数据的所有列表/图表 | `.empty` |
| **错误（行内）** | 输入框下方红字 | 字段级校验 | `.err` |
| **错误（行内）** | 卡片内红底条 | 表单级错误 | `.auth-err` |
| **错误（Toast）** | 屏幕底部浮条 | 操作结果 | `toast()` |
| **警告** | 橙色小字 | 不阻断的校验 | `.warn` `.hint-inline` |
| **警告** | 橙色提示条 | 破坏性操作前置警示 | `.warn-bar` |
| **确认** | 浏览器原生 `confirm` | 危险操作 | `window.confirm` |

## 2. 加载状态

### 2.1 应用启动 `.boot`

```html
<div class="boot">
  <span class="boot-logo"><BatteryCharging :size="22" color="#fff" /></span>
  <p>加载中…</p>
</div>
```

**样式**：`min-height: 100vh` + `background: var(--brand-grad)` + 白字白图标

**显示时机**：`store.authReady === false`，即 `store.init()` 执行期间

**为什么用渐变页而非骨架屏**：
- 启动只需 200~500ms（校验 token + 拉数据）
- 骨架屏要维护一套占位 UI，成本高收益低
- 品牌渐变页与登录页视觉一致，切换无跳变

### 2.2 按钮 loading

```vue
<button class="block" :disabled="loading" @click="submit">
  {{ loading ? '处理中…' : '登录' }}
</button>
```

**规则**：
- `loading` 时**禁用**（`:disabled`），防重复提交
- 文案改为「处理中…」，**保留按钮宽度**（避免布局跳动）
- ⚠️ 不用 spinner——文字反馈更直接，且中文语境下更自然

**注意**：登录失败曾出现过「点按钮完全无反应」，根因是 `ToastHost` 没挂在登录页分支上。**任何异步操作都必须有可见反馈**。

## 3. 空状态

### 3.1 统一结构

```html
<div class="empty">
  <div class="big"><Zap :size="30" class="ic" /></div>
  主文案
  <br />
  引导文案
</div>
```

**三要素**：
1. **图标**（30px，`opacity: .6`）——标识这里本该有什么
2. **主文案**——陈述事实（不是"暂无数据"这种死话）
3. **引导**——告诉用户下一步做什么

### 3.2 各处空状态文案

| 位置 | 文案 |
|---|---|
| 记录列表 | 还没有记录，先在上方新增一条充电账单。 |
| 概览（无 ok 段，有基准） | 该统计周期内暂无可用于累计的完整记录。**已建立 N 条基准，补录下一段即可开始测算。** |
| 概览（完全无数据） | 该统计周期内暂无可用于累计的完整记录。**请先在「记录」中新增充电记录、补全里程与车显数据。** |
| 分析（无分组） | 暂无数据 |
| 分析（无月度） | 暂无数据 |
| 车辆（未添加） | 点击选择或添加车辆 → |
| 导出按钮 | 静默 return，不弹提示（无数据时按钮本身就没意义） |

> ⚠️ **不要写"暂无数据"就完事**。必须告诉用户"为什么空"和"怎么填上"。特别是概览页的两条引导——分别对应"已建基准待补录"和"完全没录入"两种不同情况。

## 4. 错误状态

### 4.1 三层错误分级

| 层级 | 组件 | 用途 | 何时用 |
|---|---|---|---|
| **字段级** | `.err` | 单个输入框的问题 | `E ≤ 0`、`M ≤ 上段` |
| **表单级** | `.auth-err` | 整个表单的问题 | 登录失败、导入解析失败 |
| **全局级** | `toast()` | 操作结果反馈 | 保存成功、删除失败、网络错误 |

### 4.2 字段级错误 `.err`

```css
.err {
  display: block; color: var(--red); font-size: 11.5px;
  margin-top: 4px; line-height: 1.4;
}
```

**输入框联动**：加 `.invalid` 类

```css
.field input.invalid { border-color: var(--red); background: #fff5f5; }
```

**规则**：
- ❌ **只在 blur 时校验**，不实时校验——边打字边飘红是折磨
- ✅ 提交时校验所有字段，一次性展示所有错误
- ✅ 用户再次输入时**清除该字段的错误**（`@input` → 清 errors）
- ✅ 错误文案必须**说明怎么改**，不只是"不合法"

**正反例**：

| ❌ 差 | ✅ 好 |
|---|---|
| 数值错误 | 电池容量需大于 0 |
| 里程错误 | 当前里程需大于上一条的 64150 km |
| 车显错误 | 结束车显需大于起始车显（充电须增加续航） |

### 4.3 警告 `.warn` / `.hint-inline`

与错误的区别：**警告不阻断保存**。

```css
.warn        { color: var(--orange); font-size: 11.5px; }
.hint-inline { color: var(--orange); font-size: 11.5px; margin: 5px 0 0; }
```

**典型场景**：

| 警告 | 触发条件 | 为什么只警告 |
|---|---|---|
| 车显变化过小 | `R_end − R_start < 5` | 数据可能正确，但误差大 |
| 电表口径 | 表单选「电池端」时 | 提示线损，但无法强制 |
| 计算异常原因 | `err` 状态的记录 | 已在列表展示，不阻断 |

**口径警示文案**：

> ⚠️ 电池端与电网端相差约 10% 线损，请**每次保持同一口径**，否则电耗/效率测算会失真。

### 4.4 Toast

```ts
// src/utils/toast.ts
export function toast(msg: string, type: 'info'|'success'|'error' = 'info', duration = 2200) {
  const id = ++seq
  toasts.push({ id, msg, type })
  setTimeout(() => { /* 到期移除 */ }, duration)
}
```

**规则**：

| 项 | 约定 |
|---|---|
| 时长 | `2200ms`（错误可更长，建议 3000ms） |
| 位置 | 屏幕底部居中（`.toast-host`） |
| 堆叠 | 支持多条同时显示 |
| 动画 | `transition-group` 淡入淡出 |
| 桌面位置 | 从 `bottom: 28px` → `32px`（不用给 Tab 栏留位了） |

**⚠️ ToastHost 必须挂在根级**：

```vue
<!-- App.vue -->
<template>
  <div v-if="!store.authReady" class="boot">…</div>
  <AuthView v-else-if="!store.authed" />

  <div v-else class="app-shell">
    …
    <VehicleManager :open="showVehicleMgr" @close="showVehicleMgr = false" />
  </div>

  <!-- ⚠️ 必须在根级，不能挂在已登录分支里 -->
  <ToastHost />
</template>
```

> **曾发生的事故**：`ToastHost` 原本只挂在已登录分支内，导致登录页调用 `toast('邮箱或密码错误')` 时**根本没有容器渲染**，用户点登录"完全没反应"。修复时同时加了两处：① 提升到根级 ② `AuthView` 补 `.auth-err` 行内错误条（`role=alert` + `aria-live=assertive`）。
>
> **教训：任何"提示"类能力，要先问它对所有分支都可达吗。**

### 4.5 错误信息必须可操作

| ❌ 差 | ✅ 好 |
|---|---|
| 导入失败 | 导入失败：文件解析失败，请确认是导出的 JSON 备份 |
| 请求失败 (500) | 当前数据库操作失败，请稍后重试 |
| 未知错误 | 导出失败，请检查浏览器是否阻止了下载 |

**原则**：错误信息要回答「**发生了什么 + 我该做什么**」。

## 5. 确认规范

### 5.1 何时必须确认

| 操作 | 确认 | 理由 |
|---|:---:|---|
| 删除单条记录 | ✅ | 不可恢复 |
| 删除车辆 | ✅ | **级联删除全部记录** |
| 导入 JSON | ✅ | 整库覆盖 |
| 载入示例数据 | ✅ | 整库覆盖 |
| 清空全部 | ✅ | 不可恢复 |
| 编辑车辆 | ❌ | 可逆 |
| 补全记录 | ❌ | 可逆 |
| 切换车辆 | ❌ | 无副作用 |

### 5.2 确认弹窗的文案结构

**三段式**：

```
[操作后果] + [当前数据量] + [建议动作]
```

实例：

```
载入示例数据会覆盖当前账号下的全部车辆与全部充电记录
（现有 2 辆车 / 22 条记录），且不可恢复。

建议先点「导出 JSON」备份。确定继续吗？
```

```
即将用备份文件覆盖导入：2 辆车 / 22 条记录。

这会替换当前账号下的全部车辆与全部记录
（现有 2 辆车 / 22 条），原有数据不可恢复。

确定继续吗？
```

**要素**：
- ✅ 说清**后果**（不是"是否继续？"这种废话）
- ✅ 带上**当前实际条数**（用户能感知损失多大）
- ✅ 给出**补救建议**（先导出）
- ✅ 用 `\n\n` 分段，可读性更好
- ❌ 不用「确定吗？」——用户不知道在确定什么

### 5.3 破坏性操作的三重防护

当前 `导入 / 示例 / 清空` 三个操作有三层保护：

```
① 顶部橙色警示条（.warn-bar）—— 事前列出三个破坏性操作
② 二次确认（带条数）      —— 事中评估损失
③ 导入前解析校验          —— 事前拦截非法文件
```

**警示条文案**：

> 「导入 JSON」「载入示例数据」「清空全部」都会**覆盖当前账号下的全部车辆与全部记录**，且不可恢复。操作前请先「导出 JSON」备份。

> ⚠️ 这三层是 2026-10-05 补的。此前「载入示例数据」跟「导出 JSON」长得一模一样，点一下**全部记录就没了**。**新增任何破坏性操作时必须同步加这三层。**

## 6. 图表的空数据处理

| 情况 | 处理 |
|---|---|
| 无记录 | 不渲染图表区（`v-if="hasChart"`），显示空状态 |
| 某序列全 `null` | ECharts 自动断点，不画线 |
| 单点数据 | 正常显示（`smooth: true` 对单点无影响） |
| 密度过高 | 依赖 ECharts `axisLabel` 默认 interval 自动抽稀 |
| 数值跨度大 | 充电时长图用**双 Y 轴**（时长的柱高会被度数压成线） |

**双轴图例要单独说明**：因为两个轴的颜色与单轴图不同（时长=绿、度数=橙），且加了 `平均 X h · Y kWh` 的辅助文案。

## 7. 键盘与无障碍

| 项 | 实现 |
|---|---|
| 表单回车提交 | `@keyup.enter="submit"` |
| 错误条播报 | `.auth-err` 加 `role="alert" aria-live="assertive"` |
| 图片 alt | 装饰性 SVG 用 `aria-hidden` 或空 alt |
| 图标按钮标签 | `title` 属性（如铅笔 `title="编辑车辆（打开车辆管理）"`） |
| 触控尺寸 | 最小 30×30px（`.icon-btn`），移动端主要按钮 ≥ 44px |

**待加强**：
- ⬜ 弹窗打开时未做焦点捕获（`focus-trap`）
- ⬜ 未做 `Esc` 关闭弹窗
- ⬜ 图表无文字替代（屏幕阅读器无法读取图表数据）

## 8. 状态实现速查

| 需求 | 用什么 |
|---|---|
| 启动加载 | `.boot` 全屏渐变 |
| 提交中 | `:disabled` + 文案改「处理中…」 |
| 列表无数据 | `.empty` + 图标 + 引导 |
| 单字段错 | `.err` + `input.invalid` |
| 表单级错 | `.auth-err`（红底条） |
| 操作成功 | `toast(msg, 'success')` |
| 操作失败 | `toast(errMsg(e), 'error')` |
| 不阻断的提醒 | `.warn` / `.hint-inline`（橙色） |
| 危险操作警告 | `.warn-bar`（橙色条 + 图标） |
| 危险操作确认 | `confirm()` 三段式文案 |
| 数据状态标记 | `.badge.ok/.pending/.err/.baseline` |
