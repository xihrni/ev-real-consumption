# 12 · 前端架构说明

> 说明 Pinia 状态树、全量重算链路、组件职责与 API 层协作
> 代码规模：前端 2664 行 / 44 个源文件

---

## 1. 技术选型理由

| 选型 | 理由 |
|---|---|
| **无路由库** | 只有 5 个 Tab，用 `ref<Tab>` 切换即可，省下 30KB+ 依赖 |
| **Pinia** | 状态跨 5 个页面共享（车辆、记录、当前车），需要单例 |
| **ECharts 全量引入** | 图表复杂（双轴/面积/分组柱），按需引入收益有限 |
| **`utils/calc.ts` 纯函数** | 可独立测试与验证，不依赖 store |
| **CSS 变量驱动响应式** | 无需 CSS 预处理器，减少构建链路 |

## 2. 状态树

```ts
// src/store/useAppStore.ts（466 行）
{
  // ── 认证 ──
  authReady: boolean        // init() 是否完成（控制启动页）
  authed: boolean           // 是否已登录（控制登录页/主应用）
  userId: string | null
  userEmail: string | null
  authError: string | null  // 登录/注册错误（行内展示）

  // ── 数据 ──
  vehicles: Vehicle[]       // 当前用户的全部车辆
  allSessions: ChargeSession[]  // 全部记录（多车）
  currentVehicleId: string | null

  // ── 派生（computed）──
  vehicle: Vehicle | null   // 当前车辆
  sessions: ChargeSession[] // 当前车辆的记录
  computed: ComputeResult   // ★ 测算结果
  summary: { ok, baseline, pending, err, total }
  loaded: boolean
}
```

**唯一数据源原则**：所有页面都从 store 取数据，组件内部不持有业务数据的副本。

### 2.1 派生链

```
vehicles + allSessions + currentVehicleId
        ↓ (computed)
computed  ← utils/calc.ts 的 computeAll()  ← ★ 纯函数
        ↓
OverviewView / AnalysisView / SessionList 各自再加工
```

`computed: ComputeResult` 是最核心的派生值——**所有页面共享同一次计算结果**，Vue 的 computed 缓存保证了它只在依赖变化时重算。

## 3. 全量重算链路

### 3.1 触发方式

```ts
// 任意写操作后，调用 persistCurrent() 重算
async addVehicle()      → persistCurrent()
async updateVehicle()   → persistCurrent()
async deleteVehicle()   → persistCurrent()
async addSession()      → persistCurrent()
async updateSession()   → persistCurrent()
async deleteSession()   → persistCurrent()
async loadDemo()        → persistCurrent()
async importData()      → persistCurrent()
async clearAll()        → persistCurrent()
```

**不直接调 `computeAll`**，而是让 Vue 的 computed 自动重算：

```
数据变更 → computed 依赖失效 → 重新执行 computeAll() → 所有引用页面更新
```

### 3.2 为什么全量而非增量

| 方案 | 问题 |
|---|---|
| 增量重算 | `dRdep` 依赖**上一条的 `R_end`**，改一条会连锁影响后续所有段。增量极易算错 |
| 全量重算 | O(n)，n ≤ 数百条时 < 1ms；**彻底避免累积误差** |

**取舍理由**：数据类应用的核心价值是**正确性**。0.1% 的性能损失换取"永远不会算错"，值得。

### 3.3 幂等性

`computeAll(vehicle, sessions)` 是纯函数：

- 同样的输入必得同样的输出
- 多次计算不产生累积误差
- **可脱离 UI 独立验证**（2026-10-05 就是这么做的复算）

## 4. 组件职责矩阵

| 组件 | 行数 | 职责 | 不负责 |
|---|:---:|---|---|
| `App.vue` | 157 | 根布局、Tab 切换、全局弹层 | 业务逻辑 |
| `BaseChart.vue` | 40 | ECharts 封装、resize 监听 | 图表配置 |
| `VehicleCard.vue` | 109 | Hero 卡展示 | 编辑逻辑（发事件给父组件） |
| `VehicleManager.vue` | 187 | 车辆增删改弹层 | store 直接调用 |
| `VehicleConfig.vue` | 97 | 车辆数值表单 | 提交 |
| `SessionForm.vue` | 134 | 记录录入/补全表单 | 提交 |
| `SessionList.vue` | 84 | 记录列表、状态徽章 | 编辑（发事件） |
| `SessionEditModal.vue` | 191 | 记录编辑弹层 | 提交 |
| `ToastHost.vue` | 11 | 渲染 Toast 队列 | 触发（用 `toast()`） |

### 4.1 数据流方向

```
App.vue
  ├─▶ VehicleCard  ──emit('switch-vehicle')──▶ App 打开 VehicleManager
  ├─▶ RecordsView  ──▶ SessionForm（直接调 store）
  │                  └─▶ SessionList ──emit('edit')──▶ SessionEditModal
  ├─▶ OverviewView / AnalysisView / DataView（直接读 store.computed）
  └─▶ VehicleManager（直接调 store）
```

**原则**：**展示组件不调 store，写操作通过 `emit` 上抛**。`SessionForm` 例外——它是录入入口，直接调 store 更合理。

### 4.2 弹层为什么在 App.vue 而非页面内

车辆管理是**全局**的：概览页、记录页、分析页都要能打开它。放在 `App.vue` 作为根级子组件，避免每页各写一份。

## 5. API 层

### 5.1 分层

```
组件 → store 动作 → api/*.ts → api/client.ts → fetch → Express
```

**`api/client.ts` 的三个职责**：

```ts
// 1. token 注入
if (authToken) headers.set('Authorization', `Bearer ${authToken}`)

// 2. 统一错误处理
if (!res.ok) throw new ApiError(res.status, extractErrorMessage(data))

// 3. 响应解析（容忍空 body）
const text = await res.text()
let data = text ? JSON.parse(text) : null
```

### 5.2 token 的模块级变量陷阱

```ts
let authToken: string | null = readToken()   // ⚠️ 模块加载时读一次

export function setToken(t: string | null) {
  authToken = t                                // 同步更新内存
  localStorage.setItem('ev_token_v1', t)        // 同步更新存储
}
```

**⚠️ 直接写 `localStorage` 不会更新 `authToken`**。自动化测试时注入 token 必须走：

```js
// ✅ 正确（Playwright）
await page.goto(url)
await page.evaluate(t => localStorage.setItem('ev_token_v1', t), token)
await page.goto(url)     // 重新加载，让模块重新初始化
```

**这个特性反而方便了调试**——之前验证线上 UI 就是靠它实现免密码访问。

### 5.3 字段转换双层

```
DB 行（下划线）
  ↓ server/src/serialize.js  vehicleRow() / sessionRow()
API JSON（下划线 / 混合）
  ↓ store 的 normVehicle() / normSession()
store 数据（驼峰 + 业务字段保持原样）
```

⚠️ 详见 [10-数据模型 §7](10-数据模型.md)。

## 6. 图表封装

### 6.1 BaseChart

```vue
<div ref="el" :style="{ width: '100%', height: height || 'var(--chart-h, 220px)' }"></div>
```

**高度来源**：CSS 变量 `--chart-h`，在 `style.css` 的断点里集中管理（移动 220 / 桌面 340 / 超宽 400）。`height` prop 可覆盖，保留给未来的小图场景。

**生命周期**：

```
onMounted → nextTick → echarts.init → setOption
watch(option, deep) → setOption(opt, true)   // true = 不合并，完全替换
onBeforeUnmount → removeEventListener + dispose
```

**⚠️ resize 只绑 `window.resize`**。若容器自身尺寸变化（如侧栏折叠），图表不会自适应。当前无此场景，暂不处理。

### 6.2 图表配置要点

| 图表 | 要点 |
|---|---|
| 折线（电耗/均价） | `areaStyle` 渐变（`color + '33'` → `color + '05'`）、`smooth: true` |
| 分组柱（对比） | 两 series 颜色 = 语义色、`barWidth: '32%'` |
| 分组柱（时长+度数） | **双 Y 轴**、`legend` 右上、`formatter` 自定义 tooltip |
| 电价柱（分析） | `barMaxWidth: 72`（宽屏下单分类时防止柱子撑满） |
| 全局 | `axisLine`/`splitLine` 用浅灰 `--border` 系，标签 `fontSize: 10` |

**双轴必要性**（`OverviewView` 的充电时长图）：

```js
yAxis: [
  { name: 'kWh', ... },   // 左轴：充电度数 10~50
  { name: 'h', splitLine: { show: false } }  // 右轴：充电时长 0~2
]
series: [
  { name: '充电时长', yAxisIndex: 1 },   // 走右轴
  { name: '充电度数', yAxisIndex: 0 }    // 走左轴
]
```

**共用一轴会导致时长柱被压成看不见的线**（量纲差 25 倍）。

## 7. 路由方案

**没有路由库**。`App.vue` 用一个 `ref` 切换：

```ts
type Tab = 'overview' | 'records' | 'analysis' | 'data' | 'help'
const tab = ref<Tab>('overview')
```

```vue
<OverviewView v-if="tab === 'overview'" />
<RecordsView v-else-if="tab === 'records'" />
<AnalysisView v-else-if="tab === 'analysis'" />
<DataView v-else-if="tab === 'data'" />
<HelpView v-else-if="tab === 'help'" />
```

**代价**：
- 无法深链接到某个 Tab（刷新后回到概览）
- 浏览器前进/后退无效

**收益**：
- 省 30KB+ 依赖
- 切换零开销
- 弹层管理集中在 `App.vue`，不需要路由守卫

**当前可接受**（单人使用，无分享链接需求）。若将来需要深链接，再引入 `vue-router`。

## 8. Service Worker 集成

```ts
// main.ts
if ('serviceWorker' in navigator && import.meta.env.PROD) {
  const reg = await navigator.serviceWorker.register('/sw.js')
  reg.update()                    // 主动检查更新
  navigator.serviceWorker.addEventListener('controllerchange', () => location.reload())
}
```

**⚠️ `controllerchange` 自动 reload 的风险**：如果 SW 更新频繁，用户会频繁被刷新。当前策略是「HTML 导航网络优先 + SW 版本号变更才更新」，触发条件明确（见 [02-功能清单 M8](02-功能清单.md)）。

**测试注意**：自动化测试必须 `serviceWorkers: 'block'`，否则 SW 持有的 fetch 走自己的上下文，`page.route()` 拦不到 `/api`，mock 会全部失效（表现为页面停在登录页）。

## 10. 状态管理注意事项

### 10.1 `persistCurrent` 是个命名不准的方法

```ts
async persistCurrent() {
  localStorage.setItem('ev_key_current', this.currentVehicleId)   // 只存"当前车 id"
}
```

**名字暗示"持久化全部数据"，实际只存当前车 id**。别被误导。

数据本身通过 `api/*.ts` 立即落库，这个方法只是记住用户选了哪辆车。

### 10.2 不要在组件里 `watch` 整个 store

```ts
// ❌ 性能差
watch(() => store.allSessions, handler)   // 深比较 22+ 条记录

// ✅ 依赖 computed 缓存
const okSegs = computed(() => store.computed.segs.filter(s => s.status === 'ok'))
```

**原则**：能算就不要 watch。
