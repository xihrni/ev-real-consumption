## M1 账号与鉴权

### 功能点

| 编号 | 功能 | 说明 |
|---|---|---|
| M1-1 | 邮箱注册 | 密码 bcrypt(cost=10) 哈希存储 |
| M1-2 | 邮箱登录 | 返回 JWT，有效期 30 天 |
| M1-3 | 会话保持 | token 存 `localStorage['ev_token_v1']` |
| M1-4 | token 校验 | 启动时调 `GET /api/me` 验证 |
| M1-5 | 自动登出 | `/api/me` 返回 401 → 清 token → 回登录页 |
| M1-6 | 登录/注册切换 | 分段控件，切换时清除错误态 |

### 字段与校验

| 字段 | 前端校验 | 服务端校验 | DB 约束 |
|---|---|---|---|
| 邮箱 | 正则 `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` | 同左 | `UNIQUE` |
| 密码 | 长度 ≥ 6 | 同左 | — |

### 边界情况

| 情况 | 处理 |
|---|---|
| 邮箱已注册 | `409` → Toast「该邮箱已注册」 |
| 密码错误 | `401` → Toast「邮箱或密码错误」 |
| token 过期 | `/api/me` 401 → 自动登出 |
| **登录失败无任何提示** | ⚠️ **曾发生**：`ToastHost` 只挂在已登录分支，登录页失败时静默无反应。已修复——`ToastHost` 提到根级 + `AuthView` 加行内 `.auth-err` 错误条（`role=alert` + `aria-live=assertive`） |

## M2 车辆管理

### 功能点

| 编号 | 功能 | 说明 |
|---|---|---|
| M2-1 | 新增车辆 | 表单在弹层内，`保存并切换` |
| M2-2 | 编辑车辆 | **任意车可编辑**，不限于当前车 |
| M2-3 | 删除车辆 | ⚠️ 级联删除其全部记录，需确认 |
| M2-4 | 切换当前车 | 点击 Hero 卡或列表项 |
| M2-5 | 配置基线 | `M0` / `R0` |

### 字段

| 字段 | 类型 | 单位 | 校验 | 必填 |
|---|---|---|---|:---:|
| `model` | string | — | 非空（trim 后） | ✅ |
| `B` | number | kWh | > 0 | ✅ |
| `Pmax` | number | kW | > 0 | ✅ |
| `M0` | number | km | ≥ 0 | ✅ |
| `R0` | number | km | ≥ 0 | ✅ |
| `color` | string | — | — | ❌ |

### 边界情况

| 情况 | 处理 |
|---|---|
| `B` / `Pmax` 填 0 或负数 | 阻断保存：「电池容量需大于 0」 |
| `M0` / `R0` 填 0 | **允许**（新车主可能确实从 0 开始） |
| `M0` 填成当前里程 | 不阻断，但首段会判定为 `baseline` |
| 删除当前正在看的车 | 删除后自动切到第一辆车 |
| 删掉最后一辆车 | 回到 `empty-state` 占位：「点击选择或添加车辆 →」 |
| **首页铅笔点不动** | ⚠️ **曾发生**：铅笔调用的 `goToRecords()` 跳到记录页，但该页的 VehicleConfig 早已移除 → 死路。已修复：铅笔改为打开车辆管理弹层 |

## M3 充电记录

### 字段与两阶段

| 阶段 | 字段 | 必填 | 校验 |
|---|---|:---:|---|
| **一**（充电当时） | `E` 度数 kWh | ✅ | > 0 |
| **一** | `T` 时长 h | ✅ | > 0 |
| **一** | `C` 金额 ¥ | ✅ | ≥ 0 |
| **一** | `ts` 时间 | ✅ | datetime-local |
| **一** | `ctype` 充电类型 | ❌ | 枚举 |
| **一** | `meter` 度数口径 | ❌ | 枚举 |
| **一** | `note` 备注 | ❌ | — |
| **二**（回家补录） | `M` 里程 km | ❌ | > 上一条的 M |
| **二** | `R_start` 起始车显 | ❌ | < `R_end` |
| **二** | `R_end` 结束车显 | ❌ | > `R_start`，且差值 ≥ 5（否则警告） |

### 功能点

| 编号 | 功能 | 说明 |
|---|---|---|
| M3-1 | 新增记录 | 两阶段，阶段二可留空 |
| M3-2 | 补全/编辑 | 列表项点「补全 / 编辑」开弹层 |
| M3-3 | 删除 | `confirm` 二次确认 |
| M3-4 | 状态徽章 | 完整 / 基准 / 待补全 / 异常 |
| M3-5 | 异常原因展示 | `.rec .why` 逐条列出 |
| M3-6 | 未登录提示 | Tab 上有橙点（`pending + err > 0`） |

### 边界情况

| 情况 | 前端校验 | 结果 |
|---|---|---|
| `M` ≤ 上一条的 `M` | ❌ 阻断 | 「当前里程需大于上一条的 64150 km」 |
| `R_end` ≤ `R_start` | ❌ 阻断 | 「结束车显需大于起始车显（充电须增加续航）」 |
| `R_end − R_start < 5` | ⚠️ **警告不阻断** | 「车显变化过小（<5km），测算误差可能较大」 |
| `E` = 0 | ❌ 阻断 | 「充电度数需大于 0」 |
| 缺 `M` / `R_start` / `R_end` | — | 标记 `pending`，不参与累计 |
| 补全后 | — | 自动触发全量重算 |

### 状态流转

```
              录入
               ↓
        ┌──────┴──────┐
        ↓             ↓
   缺 M/R 数据     数据完整
        ↓             ↓
    [pending]    检查自洽性
        ↓             ↓
    补全编辑    ┌────┴─────┐
        ↓       ↓          ↓
   自动重算   自洽      不自洽
        ↓       ↓          ↓
    [ok]      [ok]      [err]
                   dM≤0 / dR≤0 / dRdep<0
```

## M4 测算引擎

> 完整推导见 [08-算法-测算原理](08-算法-测算原理.md)

### 输入 / 输出

**输入**：车辆配置（M0/R0）+ 记录数组

**输出**：

| 字段 | 含义 | 精度 |
|---|---|---|
| `segs[]` | 每段的状态与指标 | — |
| `cum` | 累计（M/E/C/real/price） | — |

**特性**：纯函数、幂等、O(n)

### 状态判定（顺序不可颠倒）

| 顺序 | 条件 | 状态 |
|:---:|---|---|
| 1 | 缺 `E`/`M`/`R_start`/`R_end` | `pending` |
| 2 | 无有效基线（`M0`/`R0` 缺失） | `baseline` |
| 3 | 首段且 `dM ≤ 0` | `baseline` |
| 4 | `dM ≤ 0` 或 `dR ≤ 0` 或 `dRdep < 0` | `err` |
| 5 | 其余 | `ok` |

### 边界情况

| 情况 | 处理 |
|---|---|
| `T = 0` | `power = null`（不能是 `Infinity`） |
| 除零（`dM = 0`） | 已在上游被 `dM ≤ 0` 拦截 |
| `E` 为 null | 状态 `pending`，不进入计算 |
| 记录数为 0 | `cum = null`，UI 显示空状态引导 |
| **手动改早期记录** | 全量重算，后续所有段同步更新 |
| **车显数据失真** | ⚠️ 数学上可能自洽但结果离谱（见算法文档 §8 算例），需人工核查输入 |

## M5 概览

### 4 个累计指标

| 指标 | 计算 | 展示 |
|---|---|---|
| 真实电耗 | `cumE ÷ cumM × 100` | kWh/100km |
| 用电均价 | `cumC ÷ cumM × 100` | 元/100km |
| 累计行驶 | `cumM` | km |
| 累计花费 | `cumC` | 元 |

### 4 张图表

| 图表 | 类型 | 系列 | 双轴 |
|---|---|---|:---:|
| 真实百公里电耗 | 折线（面积） | 真实电耗（绿） | ❌ |
| 百公里用电均价 | 折线（面积） | 均价（橙） | ❌ |
| 表显 vs 真实 | 分组柱 | 真实（绿）+ 表显（紫） | ❌ |
| 充电时长与度数 | 分组柱 | 时长（绿）+ 度数（橙） | ✅ 右轴=小时 |

> **双轴原因**：时长（0~2h）与度数（10~50kWh）量纲差 25 倍，共用一轴会让时长柱被压成看不见的线。详见 [05-设计规范 §2.3](05-设计规范.md)。

### 周期筛选

| 选项 | 范围 |
|---|---|
| 全部 | 全部记录 |
| 近30天 | `ts ≥ now − 30d` |
| 本月 | 自然月 |
| 上月 | 上一个自然月 |

**注意**：切换周期只影响**图表与累计**，不影响「记录」页的数据。

### 边界情况

| 情况 | 处理 |
|---|---|
| 周期内无 `ok` 段 | 显示空状态，引导补录 |
| 有 `baseline` 无 `ok` | 提示「已建立 N 条基准，补录下一段即可开始测算」 |
| 无任何记录 | 「请先在「记录」中新增充电记录、补全里程与车显数据」 |
| 图表数据稀疏 | ECharts `null` 值自动断点 |

## M6 分析

### 分组统计（按 `ctype`）

| 指标 | 计算 | 说明 |
|---|---|---|
| 充电次数 | `count` | 全部记录 |
| 总度数 | `Σ E` | 全部记录 |
| 总花费 | `Σ C` | 全部记录 |
| 行驶里程 | `Σ dM` | **仅 ok 段** |
| 真实电耗 | `Σ Econs ÷ Σ dM × 100` | **仅 ok 段** |
| 均价 | `Σ segCost ÷ Σ dM × 100` | **仅 ok 段** |
| 电价 | `Σ C ÷ Σ E` | 全部记录（与均价口径不同，注意区分） |
| 平均功率 | `avg(power)` | **仅 ok 段**，跳过 `power = null` |

分组顺序固定：家充 → 超充 → 其他（`CTYPE_ORDER`）。

### 月度报表

按 `ts` 截取年月（`slice(0,7)`），统计：充电次数、总度数、总花费、行驶里程、真实电耗、均价、电价。

**支持导出月度 CSV**（9 列）。

### 边界情况

| 情况 | 处理 |
|---|---|
| 无 `ctype` 的记录 | 归入「其他」 |
| 分组内无 ok 段 | `real`/`price` 显示 `—` |
| `Σ dM = 0` | `real`/`price` 为 `null`（避免除零） |
| 不足一个月 | 仍按月分组显示 |
| 全部为 `power = null` | `avgPower` 为 `null`，显示 `—` |

### 导出格式对比

| | JSON | CSV（记录） | CSV（月度） |
|---|---|---|---|
| 列数 | 全部字段 | **17 列** | 9 列 |
| 含原始输入 | ✅ | ✅ | ❌ |
| 含系统重算结果 | ❌ | ✅（6 个分析列） | ✅ |
| 可导入回来 | ✅ | ❌ | ❌ |
| 用途 | **完整备份** | Excel 分析 | 报表 |

**记录 CSV 列（17）**：

| 类别 | 列 |
|---|---|
| 原始输入（8） | 车辆、充电时间、度数(kWh)、时长(h)、金额(元)、度数口径、当前里程(km)、起始车显(km)、结束车显(km)、备注 |
| 状态（1） | 状态 |
| 重算分析（6） | 真实电耗(kWh/100km)、均价(元/100km)、表显电耗、功率(kW)、本段消耗(kWh)、本段里程(km) |

> 记录 CSV **按车辆分组导出**，每组独立跑测算，保证「本段」序号在多车场景下仍然正确。

**月度 CSV 列（9）**：车辆、月份、充电次数、总度数(kWh)、总花费(元)、行驶里程(km)、真实电耗(kWh/100km)、均价(元/100km)、电价(元/kWh)

> 两个 CSV 都带 **BOM 头**（`'\ufeff'`），确保 Excel 打开中文不乱码。

### 边界情况

| 情况 | 处理 |
|---|---|
| 导入非本应用 JSON | `alert`「文件解析失败，请确认是导出的 JSON 备份」 |
| 导入缺 `vehicles` | `alert` 明确提示「未找到车辆数据」 |
| 导入旧版格式（单 `vehicle`） | 兼容，包成数组 |
| 无数据时点导出 | 函数提前 return，不生成空文件 |
| 大数据量导出 | 一次性生成，⚠️ 极端情况下（万条以上）可能卡顿 |

## M8 离线与 PWA

### Service Worker 策略

| 资源类型 | 策略 | 理由 |
|---|---|---|
| HTML 导航 | **网络优先** | 保证能拿到新版本 |
| `/api` | **永远走网络** | 数据必须实时 |
| `sw.js` 本身 | 永远走网络 | 保证 SW 能更新 |
| 静态资源（JS/CSS/图标） | stale-while-revalidate | 秒开，同时后台更新 |

**配套措施**：
- `express.static` 对 `index.html` / `sw.js` / SPA 回退发 `no-cache, no-store, must-revalidate`
- `main.ts` 监听 `controllerchange` → `location.reload()`（SW 更新后自动刷新）
- 注册时调 `reg.update()`

> ⚠️ **历史教训**：早期 SW 用「缓存优先 + 版本号永不变」，导致用户几个月都看不到新版本（2026-09-18 排查过一次）。**改动 SW 策略时务必先清版本号。**

### PWA

- `manifest.webmanifest` — 图标、名称、显示模式
- `mobile-web-app-capable` + `apple-mobile-web-app-capable`（旧 iOS 兼容）
- `apple-touch-icon`
