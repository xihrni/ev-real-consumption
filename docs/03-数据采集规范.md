# 03 · 数据采集规范

> 面向用户的操作指南：**每个字段该从哪读、怎么填才准**
> 填错数据会让测算失真，详见 [08-算法原理](08-算法-测算原理.md)

---

## 1. 字段来源速查

| 字段 | 从哪读 | 精度要求 | 常见错误 |
|---|---|---|---|
| **E** 充电度数 | 充电桩 App / 账单 | **尽量精确** | ❌ 口径混用（电池端 vs 电网端） |
| **T** 充电时长 | 充电桩 App / 计时 | 精确到分钟 | ❌ 用「1 小时」这种粗值 |
| **C** 金额 | 支付账单 | 精确到分 | ❌ 混入服务费/停车费 |
| **ts** 充电时间 | 充电开始时间 | 精确到分 | ❌ 用付款时间（可能晚几小时） |
| **M** 里程 | 车辆里程表 | 整数 km | ❌ 记成"续航里程"而非总里程 |
| **R_start** 起始车显 | 车机仪表盘 | 整数 km | ❌ 充满后立刻读（应为未充前） |
| **R_end** 结束车显 | 车机仪表盘 | 整数 km | ❌ 拔枪前读（应为充满/结束） |
| **meter** 度数口径 | 充电桩 App 标注 | — | ❌ 同一账号混用两种 |
| **ctype** 充电类型 | 充电桩位置/类型 | — | ❌ 快充与家充混淆 |

## 2. 两阶段录入（重要）

### 为什么分两阶段

在停车场，你只有手机和充电桩屏幕。**要求一次填完 6 个字段是不现实的**，会导致用户直接放弃。

```
阶段一：充电当时（30 秒，在充电桩旁）
  ✅ 必填：E、T、C、ts
  ❌ 可空：M、R_start、R_end

阶段二：回家后（1 分钟）
  ✅ 补填：M、R_start、R_end
```

系统接受不完整数据，标记为「待补全」并排除出累计。补全后自动重算。

---

## 3. 阶段一：充电当时填什么

### 3.1 E（充电度数）—— 最关键

**从哪读**：充电桩屏幕、充电 App 的账单详情、支付记录

**⚠️ 口径必须一致**：

| 口径 | 含义 | 特点 |
|---|---|---|
| **电网端** | 从电网取的总电量 | **含充电枪线损**，比电池端高约 10% |
| **电池端** | 真正充进电池的电量 | 不含线损 |

不同品牌桩显示的口径不同：
- 多数公共快充桩显示**电网端**
- 部分家用桩显示**电池端**
- 充电 App 可能两个都显示

**做法**：在表单的「度数口径」开关里选一次，**之后每次录入都选同样的那个**。

> **混用会怎样**：假设家充记的是电池端（低 10%），快充记的是电网端（高 10%），算出的 `k` 会前后不一致，同一辆车的电耗曲线会毫无规律地跳动。

### 3.2 T（充电时长）

**从哪读**：充电桩计时、App 显示

- 部分桩按 `0.1 小时` 粒度显示（如 8.15 时 = 8 小时 9 分）
- 表单支持「时 + 分」分开填

**注意**：`T = 0` 时平均功率无意义，系统会置 `null`。

### 3.3 C（金额）

**从哪读**：支付账单

- ⚠️ 部分充电桩有**服务费 + 停车费 + 占位费**，是否计入要看你的实际支出
- 建议统一口径：**只记电费**，或**记总支出**，但不要混

### 3.4 ts（充电时间）

**用充电开始时间**，不是付款时间。

理由：付款可能在充电结束后十几分钟才发生（如快充充满后自动跳闸，账单延迟生成）。用付款时间会打乱记录顺序，导致 `dM` 计算出错。

### 3.5 meter（度数口径）

见 §3.1。表单有「电网端 / 电池端」两个按钮切换。

### 3.6 ctype（充电类型）

| 值 | 什么时候选 |
|---|---|
| 家充 | 家用固定桩、物业桩 |
| 超充 | 高速服务区、第三方快充、商场地库快充 |
| 其他 | 换电、借用桩、说不清的 |

**不影响**电耗与均价计算，仅用于分析页分组统计。填错只影响分组报表。

### 3.7 note（备注）

建议在**推算的历史数据**上标注，如「按 0.85h × 功率反推」「桩只给时长，度数估算」。后续回看时能立刻分辨哪些是精确值、哪些是估算值。

## 4. 阶段二：回家后补什么

### 4.1 M（里程）—— 用总里程，不是续航

**这是最容易填错的一项。**

| ✅ 正确 | ❌ 错误 |
|---|---|
| 仪表盘**总里程**（如 `64208`） | 车显**续航里程**（如 `180`） |
| 每次充电累加的读数 | "这次跑了 180 公里" |

**为什么要总里程**：算法用它算 `dM = M − prev.M`，即实际行驶距离。

**填法**：
1. 看车辆仪表盘的 `ODO` / `总里程`
2. 减去上一条记录填的 M
3. 差值就是这段跑的里程

⚠️ **必须严格递增**，且 `M > 上一条的 M`。系统会校验，不满足会阻断。

### 4.2 R_start（起始车显）

**在插枪前读**，或**从上次拔枪时的记录里继承**。

**关键**：它是「这次充电开始时，车上还有多少续航」。

```
上次充满：车显 501
这次插枪：车显 241
→ R_start = 241
```

> **常见错误**：插枪前车机可能已经在慢慢更新，或者因为上次没充满导致起点很低。**只要是"插枪那一刻"的值就行**，不必纠结精度。

### 4.3 R_end（结束车显）

**充满后读**（推荐），或拔枪前读。

```
充满：车显 501
→ R_end = 501
```

**要求**：
- `R_end > R_start`（充电必须增加续航）
- ⚠️ 若 `R_end − R_start < 5`，系统会警告「车显变化过小，测算误差可能较大」

> **为什么重要**：`k = E ÷ (R_end − R_start)`。这个差值是分母，越小则 k 越敏感，误差放大得越厉害。

### 4.4 为什么车显数据会失真

车显续航是**估算值**，受以下因素影响：

| 因素 | 影响 |
|---|---|
| 温度 | 低温时车显虚高，实际续航打折 |
| 车速 | 高速时实际电耗远高于车显假设 |
| 载重 / 空调 | 满载开空调时偏差最大 |
| 车机标定 | 不同批次标定不同 |

**结果**：可能出现「车显掉了 38 km 但实际跑了 148 km」这种矛盾数据。

**这不是系统 bug**——数学上 `dM>0`、`dR>0`、`dRdep>0` 三条都满足，计算是自洽的。但**结果明显偏离常识**。

**处理建议**：遇到离谱的值，**优先怀疑车显数据**，回查当时的仪表盘照片。没有照片就按充电桩 App 的数据重新估算 `R_start`（充满的桩，上一条的 `R_end` 可以作为这次的 `R_start`）。

## 5. M0 / R0 基线配置（首次使用）

### 5.1 是什么

首条记录没有"上一段"可参照，需要一个**起点**：

| 字段 | 含义 |
|---|---|
| **M0** | 开始用本工具记录之前，**上一次充电结束时**的里程表读数 |
| **R0** | 那时的车显剩余续航 |

### 5.2 怎么取

| 途径 | 步骤 |
|---|---|
| **翻历史** | 充电 App 里有历史订单，找到记录开始前的那次，看时间 |
| **加油/充电小票** | 部分充电桩小票会打印里程 |
| **仪表盘拍照** | 最直接：下次充电时拍一张总里程 + 车显 |
| **估个大概** | 留下边，后续用「补全」修正 |

### 5.3 常见错误

| ❌ 错误填法 | 后果 | 正确填法 |
|---|---|---|
| 填**当前**里程 | `dM = M − M0 ≤ 0` → 首段变「基准」不参与计算 | 填**记录开始之前**的里程 |
| 填 0 | 首段必然变「基准」 | 填真实历史值 |
| 随便填个大概 | 同上 | 尽量准确，或留空 |

**好消息**：填错**不会损坏数据**。系统会自动把首段降级为「基准记录」，从第二条开始正常计算。

### 5.4 忘记配怎么办

不影响使用。首条自动成为「基准记录」，在记录列表里显示为 `基准` 徽章。等第二条录入后就能正常测算了。

**但建议配**——配了首条就能出数据，多一条有效记录。

## 6. 电摩的特别说明

### 6.1 铅酸电池 72V20Ah = 1.44 度电

```
72V × 20Ah = 1440 Wh = 1.44 kWh
```

但**满充时从电网取的电量会更多**（充电损耗 + 涓流阶段），实测约 **2.2~2.4 度**。所以电摩的 `B` 填 1.44（电池标称），`E` 填**桩显示的实际度数**（2.2~2.4）。

### 6.2 充满自停场景

电摩充满后自动断电，`R_end` 恒等于满值（如 60），此时：

```
dRdep = prev.R_end − R_start = 60 − R_start
dR    = R_end − R_start     = 60 − R_start
两者相等 → k 被约掉 → Econs = E
→ 退化为「充电度数 ÷ 里程 × 100」
```

**结论**：电摩场景下**只需填对 E 和 M**，车显填个大概即可。

#### 起始车显的约定填法：`R_start = 60 − 本段里程`

虽然不影响结果，但历史记录一直按这个规律填，保持一致便于核对：

| 日期 | 本段里程 | 起始车显 | 60 − 里程 | 一致 |
|---|---:|---:|:---:|
| 2026-08-21 | 51 | 9 | 9 | ✓ |
| 2026-09-19 | 46 | 14 | 14 | ✓ |
| 2026-09-29 | 27 | 33 | 33 | ✓ |
| 2026-10-15 | 47 | 13 | 13 | ✓ |

含义：把 60 km 当满电续航，按实际跑的里程线性折算剩余。**只需 ≤ 60 即可**，上式只是为了口径统一。

#### 计时桩的度数换算

拿到「结算功率」和「充电时长」两个值即可：

```
E = 结算功率(kW) × 时长(h)
```

实例（2026-10-15）：`292 W = 0.292 kW`，时长 `7:09:04 = 7.1511 h`
→ `E = 0.292 × 7.1511 = 2.088 → 2.09 kWh`，与账单 3.38 元对比得单位电价 **1.62 元/度**，与历史一致。

> ⚠️ 计时桩按平均功率计费，涓流阶段会略微低估实际充入量，误差约 ±5%。所以备注里务必标注推算方式。

### 6.3 按时间计费的桩

部分电摩充电桩**只给「充电时长 + 金额」，不给度数**。处理办法：

```
度数 = 功率 × 时长
```

**反推示例**（实测数据）：

| 订单 | 时长 | 金额 | 推算度数 |
|---|---:|---:|---:|
| 1 | 8.15 h | 3.83 元 | 2.36 度 |
| 2 | 7.24 h | 3.38 元 | 2.11 度 |
| 3 | 4.25 h | 2.03 元 | 1.23 度 |

**功率假设**：0.29 kW（= 72V×20Ah 的实际充电功率经验值）

**反推后务必在 `note` 里标注**，如「按 0.29kW × 时长反推」，方便日后核查。

## 7. 数据质量自查

录入一批数据后，在「分析」页按这两项交叉验证：

### 7.1 隐含单位电价

```
单位电价 = Σ 分摊费用 ÷ Σ 真实耗电
```

**正常范围**：

| 场景 | 区间 | 说明 |
|---|---|---|
| 家充为主 | 0.3 ~ 0.6 元/度 | 阶梯电价 |
| 快充为主 | 0.8 ~ 1.5 元/度 | 含服务费 |
| 电摩按时计费 | 1.5 ~ 2.0 元/度 | 计时桩单价高 |

**实测参考**（2026-10-05 复算）：
- 欧拉好猫 **0.905 元/度**（家充+快充混合）✅
- 电摩 **1.621 元/度**（按时间计费桩）✅

**若算出的电价明显异常**，说明 `E` 或 `C` 录错了。

### 7.2 表显 vs 真实电耗

在「概览」页对比「表显电耗 vs 真实电耗」图：

| 差值 | 可能原因 |
|---|---|
| 差 < 10% | 数据质量好 |
| 差 10~25% | 正常范围（车机乐观标定） |
| 差 > 30% | ① 车机标定不准 ② 车显数据有误 ③ 口径混用 |

## 8. 常见问题速查

| 问题 | 原因 | 解决 |
|---|---|---|
| 首条记录不参与计算 | `M0` 没配或填错 | 车辆管理里配 `M0`/`R0`，或接受首条为基准 |
| 均价出现离谱尖峰 | 早期 bug（已修） | 升级到最新版；如仍异常，删掉该条重录 |
| 电耗忽高忽低 | 车显数据波动大 | 检查 `R_start`/`R_end` 读取时机，尽量同条件录入 |
| 「异常」提示里程未增加 | 两条记录 M 相同或倒序 | 检查是否重复录入，或 M 填成了续航 |
| 「异常」提示上段结束车显 < 本段起始 | 中间漏记了一次充电 | 补录漏掉的记录 |
| 充电度数变化过大 | 口径混用 | 统一选「电网端」或「电池端」 |
| 功率显示 `—` | 该条 `T = 0` | 补填充电时长 |

## 9. 录入最佳实践

| 建议 | 理由 |
|---|---|
| **充完立刻记账单** | 趁信息新鲜，`E`/`T`/`C` 不会忘 |
| **补录时顺手拍仪表盘** | 车显数据日后极难回忆 |
| **同口径录入** | 避免 `k` 前后不一致 |
| **里程读 ODO 总里程** | 不是续航里程 |
| **推算数据必须标注** | `note` 里写明推算方式 |
| **定期导出 JSON** | 服务端故障时的唯一兜底 |
| **换季前检查一次车显** | 温度对车显影响大 |
